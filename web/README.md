# Site (Astro rebuild)

The new personal site, built with Astro. It replaces the old Jekyll (al-folio)
site. Warm "Ephemeris" theme: cream paper, ink text, vermilion accent, Manrope +
IBM Plex Mono, with a fixed light celestial background.

## Run it

    cd web
    npm install
    npm run dev        # local dev server
    npm run build      # static build to web/dist
    npm run preview    # serve the built site

## Pages

- `/` — lean hero + selected work + latest writing
- `/about/` — full bio
- `/blog/` and `/blog/:year/:slug/` — writing (URLs preserved from the old site)
- `/publications/` — papers, from `src/data/publications.ts`
- `/projects/` — from `src/data/projects.json` (generated by `scripts/migrate-projects.mjs`)
- `/cv/` — embeds the CV PDF
- `/news/` — from `src/data/news.ts`

## Before going live

1. Set your real X/Twitter handle in `src/consts.ts` (`SOCIALS.x`).
2. Fill `GISCUS.repoId` and `GISCUS.categoryId` in `src/consts.ts` (from
   https://giscus.app after enabling Discussions on the repo) to turn on
   post comments.
3. To deploy: in `.github/workflows/deploy-astro.yml`, uncomment the `push`
   trigger, and delete the old Jekyll workflow `.github/workflows/deploy.yml`.
   The workflow builds `web/`, copies `benchmark-registry/` into the output so
   `/benchmark-registry` keeps working, and publishes to Pages.

## Notes

- The old Jekyll files (`_posts`, `_pages`, `_config.yml`, `Gemfile`, etc.) are
  still in the repo on this branch. Remove them once the Astro site is live.
- `benchmark-registry/` stays at the repo root and is copied into the build by
  the deploy workflow (not duplicated in source).
